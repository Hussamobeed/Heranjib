# ربط Heranjib بـ SABA

التطبيق مخصص لهاتف أندرويد واحد مرتبط بحساب SABA. يحتفظ بالمخزون والمبيعات في الهاتف، ويستقبل الدفعات ويرفع المعاملات عبر دالة Supabase. لا يستخدم Google Sheets للاستيراد أو المزامنة.

## التحديث من الإصدار السابق

1. صدّر نسخة البيانات من إعدادات التطبيق واحتفظ بها قبل التحديث.
2. انشر ترحيل قاعدة البيانات وملفات دالة api في مستودع SABA أولاً. اتبع دليل `docs/HERANJIB_AR.md` هناك.
3. حمّل ملف التطبيق من ناتج GitHub Actions بعد نجاح البناء. ثبّت التحديث فوق النسخة الحالية باستخدام توقيع التطبيق نفسه. لا تحذف التطبيق ولا تمسح بياناته.
4. ينتقل التخزين من الإصدار 8 إلى 9 مع إبقاء المخزون والمبيعات. النسخ الأقدم من 7 تحتاج ترحيلاً مخصصاً؛ التطبيق لا يحذفها تلقائياً عند غياب مسار ترحيل.
5. من صفحة Heranjib في SABA افتح الربط وأنشئ رمزاً صالحاً لمدة 15 دقيقة.
6. من إعدادات أندرويد اضغط «ربط SABA» والصق بيانات الربط كاملة، ثم اضغط «ربط».
7. اضغط «المزامنة الآن» وانتظر ظهور المخزون والمعاملات السابقة في SABA. تمنع SABA إرسال دفعات جديدة قبل اكتمال المزامنة الأولى.

## نقل الكروت

أنشئ دفعة في SABA واستوردها إلى MikroTik. من صفحة إنشاء كروت يوزرمنجر اضغط إرسال الدفعة إلى Heranjib، أو حدد عدة ملفات محفوظة واضغط إرسال المحدد إلى Heranjib. حدد مبلغ الفئة لكل دفعة مثل 100 أو 200. ينتقل كامل محتوى الدفعة دون إدخال عدد جزئي. اضغط «إرسال إلى Heranjib». يظل الطلب بانتظار الهاتف حتى يحفظ الهاتف الكروت محلياً ويؤكد الاستلام.

تعمل المزامنة الدورية بحد أدنى 15 دقيقة، وقد يؤخرها أندرويد. استخدم المزامنة الآن لاستلام دفعة دون انتظار الموعد الدوري. الكرت المخصص للهاتف لا يعاد تخصيصه لدفعة أخرى، ولا يُعاد ضبط حالة الكرت عند تكرار الاستلام.

بعد الربط تتم إضافة المخزون من SABA. تتوقف إضافة الملفات أو إعادة كرت مرسل إلى متاح أو حذف المخزون من الهاتف. يبقى خيار تحديد كرت كمرسل متاحاً للمراجعة. ترفع المزامنة تغيير الحالة إلى SABA.

## الإرسال والمراجعة

يحجز التطبيق الكرت قبل استدعاء SMS. «أُرسل للشبكة» تعني تأكيد أندرويد إرسال كل أجزاء الرسالة، ولا تعني تأكيد استلام العميل. إذا لم يتأكد الإرسال، أو توقف التطبيق أثناءه، يبقى الكرت محجوزاً للمراجعة ولا يعاد بيعه تلقائياً. يمكن مراجعة سجل الهاتف والتواصل مع العميل قبل تحديده كمرسل.

## السجل والخصوصية

رفع سجل التطبيق متوقف افتراضياً. تفعيله من SABA يكون لساعة أو 6 ساعات أو يوم، ثم يتوقف تلقائياً. المعاملات والمخزون تستمر في المزامنة. بيانات ربط الهاتف مشفرة بمفتاح Android Keystore ولا تتضمن مفتاح خدمة Supabase أو بيانات الراوتر.

يدعم الإصدار 3.1 استعادة ملف ZIP المصدر من APK القديم. عندما تكون قاعدة الهاتف فارغة تُستعاد النسخة كاملة بعد فحص جميع الملفات، وعند وجود بيانات حالية أو بعد الربط تُدمج السجلات دون حذف الحالية أو إعادة الكرت المباع إلى متاح. الكروت المسترجعة غير المعروفة تبقى للمراجعة وتطابق مع SABA عند المزامنة. لا تعاد رسائل التحويل القديمة إلى طابور الإرسال. تحفظ النسخ الجديدة كلمات المرور والبروفايلات ومعرفات الكروت، وهي غير متوفرة أصلاً في النسخ القديمة. إعادة تثبيت التطبيق أو استبدال الهاتف تحتاج تسوية مخزون وربط من الإدارة؛ لا يمكن تسجيل هاتف ثان تلقائياً.

## تحديث الخادم للإصدار 3.1

شغّل ترحيل `20261020000200_heranjib_batch_transfers.sql` في مشروع SABA وحدّث `heranjib.ts` قبل تثبيت هذه النسخة. يحمي الترحيل المعاملات من التكرار عند تغيّر أرقام الصفوف المحلية بعد الاستعادة. لا تحذف التطبيق الحالي عند تثبيت التحديث، ويبقى توقيع GitHub نفسه.

## البحث عن كرت في الإصدار 3.2

اضغط العدسة أعلى التطبيق وأدخل رقم الكرت. يستخدم البحث ربط SABA الحالي، ويعرض اختيار الجهاز عند وجود أكثر من راوتر محفوظ فقط. يبحث الخادم في الميكروتك بمهلة 20 ثانية، ثم التقارير المالية ثم أرشيف قناة التلجرام. لا يضيف البحث حملاً دورياً؛ يبدأ عند الضغط على بحث.

تعرض الشاشة معلومات الكرت ومصدر العثور عليه. لا يظهر سعر الفئة أو التعليق، ولا يدخلان في النسخ والمشاركة. تاريخ رسالة تلجرام يبقى تاريخ رسالة وليس أول دخول أو وقت استخدام. زر النسخ ينسخ بيانات الكرت، وزر المشاركة يفتح قائمة تطبيقات الهاتف.

يتطلب البحث نشر api مع phone-card-search.js وتحديث heranjib.ts وindex.ts قبل تثبيت APK 3.2. لا يحتاج SQL أو إعادة الربط. لا يخزن الهاتف بيانات دخول الراوتر أو توكن تلجرام. يبقى المخزون والمبيعات وترحيل قاعدة البيانات والتوقيع كما في الإصدار السابق. يتحقق البناء من تطابق شهادة APK مع النسخة 3.1.
